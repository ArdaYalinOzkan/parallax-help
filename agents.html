Automation

Parallax from a command line.

A command-line interface for reading the library, starting games and editing entries. Intended for scripts and for AI assistants working on a user's library.

How to run it

There is nothing extra to install. The command line lives inside the copy of Parallax already on the machine and is reached with --cli; everything after that flag is the command. 

parallax-launcher --cli games --json
./Parallax-Launcher.AppImage --cli games --json
"C:\Path\To\Parallax Launcher.exe" --cli games --json

On Windows the installer lets you choose where it goes, so there is no single path to quote — the Start menu shortcut points at it. No window opens and no display is needed, so this works over SSH and inside a container. It exits 0 when it worked and 1 when it did not.

Worth giving it a shorter name, once:

alias parallax='parallax-launcher --cli'

If you are the agent reading this

Pass --json to everything. Output is then one JSON object with an ok field, and on failure an error code and a message written for you to act on rather than to print. The codes are stable and the messages are not, so branch on the code. 

{
  "ok": false,
  "error": "AMBIGUOUS_GAME",
  "message": "\"half\" matches 7 games: Half-Life, Half-Life 2, … Use the id."
}

Games are named by id or by name, and the name does not have to be exact — half life 2 finds Half-Life 2. When a loose name matches more than one game it refuses and lists them rather than choosing; use the id from that list. Ids are stable and never reused.

The commands

parallax accounts
parallax games [--installed] [--search TEXT] [--sort name|playtime]
parallax game <id|name>
parallax find <name> [--appid N]
parallax fields

parallax launch <id|name>
parallax add <name> [--path P] [--steam-appid N] [--platform P]
parallax set <id|name> <field> <value>
parallax scan

--account NAME works on any of them. Without it the library the app used last is chosen; where there are several and none has been used, it asks rather than guessing.

  1. games

    Every game in the library. --installed narrows it to what is on this machine, --search to names containing some text. Each carries id, name, platform, status, installed, path, playTimeHours, steamAppId, category, launchOptions and compatTool.

  2. launch

    Starts a game the way the Play button does — through Steam when the game is Steam's, otherwise by running it with whatever compatibility tool the entry is set to. It returns once the game has been handed off and does not wait for it to close. A game with a Steam id goes to Steam whether or not it is installed; one with neither a Steam id nor a location fails with NO_PATH.

  3. find

    Looks for a game on this computer without changing anything: Steam's own records first, then the usual install folders on every drive. Returns each location with the executable it would use. An empty list means it is not here — an answer, not an error.

  4. add

    Adds an entry. With --path left out it searches first and fills the location in when it finds one. A name already in the library is refused with ALREADY_THERE.

  5. set

    Changes one field. parallax fields lists what it accepts and anything else is refused rather than written. Setting path checks the location exists and moves the status to match, because a game marked installed with nowhere to launch from is a claim nothing can act on.

  6. scan

    Asks Steam what is really installed and corrects the library, reporting every entry it changed. Worth running before trusting the installed flag on a library that has been sitting a while.

What it will not do

There is no command to delete a game, and none to create, rename or delete an account. Those are the operations that cannot be taken back, and they are absent rather than merely discouraged — something that reads a web page and then decides what to do next should not be holding them. Everything here is either read-only or a change a person can undo in the window.

Artwork is not downloaded from here either. That needs API keys and a network budget, and it belongs to the window.

While the window is open

Both write to the same file, and both are allowed to. Parallax watches its library for changes it did not make and reloads when one arrives, so an edit made here shows up in an open window within a second. The one exception is a game being edited at that moment: the person holding it keeps it, and their save wins. 

parallax games --sort playtime --json | jq '.games[:5][] | .name'
parallax launch "hollow knight" --json
parallax add "Baldur's Gate 3" --json

Something missing, or a shape you would rather it returned? Open an issue — it is read.
